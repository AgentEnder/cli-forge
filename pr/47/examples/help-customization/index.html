Help & Version Customization

Demonstrates how to customize the --help and --version output for a CLI.

You can:

  • Pass a callback to .help() to customize the full help text
  • Pass a callback to .version() to customize the version output
  • Disable either flag entirely with .help(false) or .version(false)
  • Use formatHelpText on individual options for per-option customization
  • Use .catch() to customize error handling (e.g. suppress or restyle the default validation-error + help output)

Help callbacks receive a context object with:

  • args — the parsed arguments at the time --help was invoked (partial)
  • cli — the CLI instance
  • renderDefaultHelp() — renders the full default help text
  • options — configured options, each with a renderHelpText() method

Custom help callbacks are inherited by subcommands. If a subcommand does not define its own, it walks up the parent chain.

1import cliForge from 'cli-forge';
2
3const cli = cliForge('my-tool')
4  .option('verbose', {
5    type: 'boolean',
6    alias: ['v'],
7    description: 'Enable verbose output',
8  })
9  // Custom help callback — receives a context object you can destructure.
10  // The callback is inherited by subcommands that don't define their own.
11  .help(({ args, renderDefaultHelp, options }) => {
12    // Add a branded header with the tool version
13    let output = `my-tool v1.0.0\n\n${renderDefaultHelp()}`;
14
15    // `args` is partial (parse may not have finished), so check safely
16    if (args.verbose) {
17      output += '\n\nVERBOSE HELP: extra debugging information shown here';
18    }
19
20    // `options` gives you each configured option with a renderHelpText()
21    // method that respects per-option formatHelpText overrides — useful
22    // for building fully custom help layouts.
23    const userOptions = options.filter(
24      (o) => o.key !== 'help' && o.key !== 'version'
25    );
26    output += `\n\n${userOptions.length} user-defined option(s)`;
27
28    return output;
29  })
30  // Customize version output. Set the version string first, then
31  // provide a callback that wraps the default output.
32  .version('1.0.0')
33  .version(({ renderDefaultVersion }) => {
34    return `my-tool v${renderDefaultVersion()} (custom build)`;
35  })
36  .option('output', {
37    type: 'string',
38    description: 'Output directory',
39    default: './dist',
40    // Per-option help customization: the callback receives the option
41    // config and the default text, and returns the replacement line.
42    formatHelpText: (_option, _defaultText) => {
43      return '  --output - Output directory [output directory path] [default: ./dist]';
44    },
45  })
46  // .catch() replaces the default validation-error handler, which
47  // normally prints help + error messages and exits. This lets you
48  // control what users see on bad input.
49  .catch((error, { renderDefaultHelp, exit }) => {
50    if (error instanceof Error) {
51      console.error(`Error: ${error.message}`);
52    }
53    console.error(`\nRun "my-tool --help" for usage information.`);
54    exit(1);
55  })
56  .command('serve', {
57    description: 'Start a development server',
58    builder: (args) =>
59      args.option('port', {
60        type: 'number',
61        description: 'Port to listen on',
62        default: 3000,
63      }),
64    handler: (args) => {
65      console.log(`Serving on port ${args.port}`);
66    },
67  })
68  .command('build', {
69    description: 'Build the project',
70    handler: (args) => {
71      console.log(`Building to ${args.output}`);
72    },
73  });
74
75export default cli;
76
77if (require.main === module) {
78  (async () => {
79    await cli.forge();
80  })();
